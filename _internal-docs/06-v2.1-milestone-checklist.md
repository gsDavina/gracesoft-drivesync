# GraceSoft DriveSync — v2.1 Milestone Checklist (Document Type Expansion)

Extends v2's extraction pipeline (M5) from Google Docs/Sheets/Slides + text-layer PDFs to every common document type a connected folder is likely to hold. Shipped as a **v2.x minor release, not v3**: the `ExtractionResult` contract, vector ID scheme (`{fileId}-{chunkIndex}`), retrieval/MCP response shapes and required env vars all stay unchanged. Every change below is additive.

Numbering continues from v2 (M1–M18) so progress docs in `_internal-docs/progress/` never collide.

**Status (2026-11-21):** M19–M28 done (code, unit tests, progress docs). M29 docs done; the Railway staging run and production release are what's left. Full suite: 235 tests passing; lint, typecheck and build clean.

## Scope

All work lives in `src/extraction/`. `syncFolder.ts`, chunking, dedup, embeddings and the vector store already only see `{ ok, text }`, so they need no changes beyond the small, optional additions in M27/M28.

| Format | MIME type | Approach | Milestone |
|---|---|---|---|
| Word (.docx) | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `mammoth` → Markdown | M22 |
| Word 97–2003 (.doc) | `application/msword` | `word-extractor` → plain text | M22 |
| Plain text / Markdown | `text/plain`, `text/markdown` | UTF-8 decode | M23 |
| CSV / TSV | `text/csv`, `text/tab-separated-values` | UTF-8 decode | M23 |
| JSON | `application/json` | UTF-8 decode (pretty-printed) | M23 |
| HTML | `text/html` | `html-to-text` | M23 |
| Excel (.xlsx / .xls) | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `application/vnd.ms-excel` | Spreadsheet parser, **all sheets** | M24 |
| OpenDocument spreadsheet (.ods) | `application/vnd.oasis.opendocument.spreadsheet` | Spreadsheet parser, all sheets | M24 |
| Google Sheets | `application/vnd.google-apps.spreadsheet` | Export as xlsx → same parser (fixes first-sheet-only gap) | M24 |
| PowerPoint (.pptx) | `application/vnd.openxmlformats-officedocument.presentationml.presentation` | `officeparser` | M25 |
| OpenDocument text / presentation (.odt / .odp) | `application/vnd.oasis.opendocument.text`, `application/vnd.oasis.opendocument.presentation` | `officeparser` | M25 |
| Google Docs | `application/vnd.google-apps.document` | Export as `text/markdown` instead of `text/plain` (behind a flag) | M26 |

## Milestones

- [x] **M19. Version & release framing** — Bump `package.json` from `0.1.0` to `2.0.0` (matching how the docs already refer to v2) so this release can ship as `2.1.0`. Add a `CHANGELOG.md` with a v2.0.0 baseline entry. No code changes. → [progress](progress/M19-version-and-release-framing.md)
- [x] **M20. Extractor registry refactor** — Replace the `switch` in `textExtractor.ts` with a MIME-type → extractor registry. One file per family under `src/extraction/extractors/` (`googleNative.ts`, `pdf.ts`, then one per later milestone). Each extractor gets the same dependency-injection seam as today's `PdfParser`, so tests use fakes and need no real libraries or bytes. `createTextExtractor` becomes a thin dispatcher: look up by `mimeType`, otherwise `unsupported-mime-type`. **No behaviour change**: every existing `textExtractor.test.ts` case passes unmodified. This is a pure refactor and should land on its own before any new format. → [progress](progress/M20-extractor-registry-refactor.md)
- [x] **M21. Download safety guards** — Prerequisite for every binary format, given GraceSoft's security-first stance. → [progress](progress/M21-download-safety-guards.md)
  - Add `size` to the `listFiles` `fields` list and to `DriveFileMeta` (optional; Google-native files have no size).
  - New optional env var `MAX_EXTRACT_BYTES` with a sensible default (e.g. 25 MB). Files above it fail closed as `file-too-large` **before** `downloadFile` is called.
  - Per-file parse timeout (e.g. `EXTRACT_TIMEOUT_MS`, default 30 s) → `extraction-timeout`.
  - Zip-bomb protection for OOXML/ODF (docx/xlsx/pptx/odt/ods/odp are zip archives): cap total decompressed size and entry count → `archive-too-large`.
  - New fail-closed reasons added to the `ExtractionResult` union. This is additive and consistent with the M5 principle "fail closed with a specific reason".
- [x] **M22. Word documents** — `.docx` via `mammoth` converted to **Markdown**, so real heading styles become `#` headings that M6's `MARKDOWN_HEADING` detection picks up (better than the Title Case heuristic used for plain-text exports). Legacy `.doc` via `word-extractor` (plain text only, so it falls back to the heuristic). Corrupt or password-protected files fail closed (`corrupt-file` / `password-protected`) instead of throwing a generic error. → [progress](progress/M22-word-documents.md)
- [x] **M23. Plain-text family** — `txt`, `md`, `csv`, `tsv`, `json`, `html`. Decode as UTF-8, stripping the BOM if present. Invalid UTF-8 fails closed as `unsupported-encoding` rather than embedding mojibake. HTML goes through `html-to-text` (drop scripts/styles; keep headings as Markdown). JSON is pretty-printed before chunking so token boundaries fall on readable lines. → [progress](progress/M23-plain-text-family.md)
- [x] **M24. Spreadsheets (all sheets)** — `.xlsx`, `.xls`, `.ods`, and Google Sheets re-routed through `exportAsText(id, xlsx MIME)` → the same parser. Output is one Markdown section per sheet (`## <Sheet name>` followed by CSV-ish rows), so each sheet becomes its own chunk section. Closes the M5 "first sheet only" gap. → [progress](progress/M24-spreadsheets.md) — **parser decision:** in-house xlsx/ods reader on `fflate` (SheetJS CDN tarballs are blocked by this environment's npm policy, `xlsx@0.18.5` is unmaintained, `exceljs` is xlsx-only, `officeparser@8` needs Node 22+). **`.xls` deferred.** Google Sheets use the new binary `DriveClient.exportFile`, not `exportAsText` (which would corrupt xlsx bytes).
  - **Decision needed — parser choice:** the `xlsx` package on the npm registry (0.18.5) is unmaintained with known CVEs; current SheetJS ships from SheetJS's own CDN. Alternatives are `exceljs` (xlsx only, no `.xls`/`.ods`) or `officeparser`. Record the choice and why in the progress doc.
  - **Release note:** every existing Google Sheet's content hash changes, which causes a one-time re-embed of all Sheets on the first sync after deploy.
- [x] **M25. Presentations & OpenDocument** — `.pptx`, `.odp`, `.odt` via `officeparser`. Slide text in slide order; speaker notes included if the parser exposes them (record the decision). Legacy `.ppt` is deferred (see below). → [progress](progress/M25-presentations-and-opendocument.md) — in-house reader instead of `officeparser` (Node 22+ requirement, heavy deps). Speaker notes **included**.
- [x] **M26. Google Docs Markdown export (flagged)** — New optional env var `GOOGLE_DOCS_EXPORT_FORMAT=text|markdown`, default `text` so existing deployments see no change. `markdown` uses Drive's `text/markdown` export and gives Docs real headings for chunking. **Release note:** turning it on changes every Doc's content hash, causing a one-time full re-embed of all Docs. Document the expected OpenAI cost in the runbook. → [progress](progress/M26-google-docs-markdown-export.md)
- [x] **M27. Skipped-file state** — Today a file that fails extraction is never written by `upsertSynced`, so every sync run treats it as "added" again and logs another failure. That's harmless with 4 types but noisy with a full Drive of images and videos. → [progress](progress/M27-skipped-file-state.md) — permanent = every specific reason except `extraction-timeout`; skipped files are re-evaluated when the extractor registry's `capabilityVersion` changes. Migration generated but not yet applied to a real DB.
  - Additive Prisma migration: `DriveFile.status` (`SYNCED` | `SKIPPED`) + `skipReason`.
  - For *permanent* reasons only (`unsupported-mime-type`, `file-too-large`, `password-protected`, `scanned-pdf-ocr-not-implemented`): record the file as `SKIPPED` with its `modifiedTime`, so it's only retried once the file actually changes.
  - *Transient* failures (thrown errors, timeouts, Drive 5xx) keep today's retry-every-run behaviour.
  - `/status` and `/audit` report skipped counts and reasons per folder.
- [x] **M28. `mimeType` in vector metadata** — Add `mimeType` to the upserted vector metadata in `syncFolder.ts` and return it in retrieval and MCP results. Additive, so existing consumers (Sentinel Chat) are unaffected. Lets clients filter or label results by file type. Only applies to vectors written after deploy unless a resync is run (document this). → [progress](progress/M28-mimetype-in-vector-metadata.md)
- [ ] **M29. Docs & release** — README "Supported file types" table (from the Scope table above), `docs/architecture.md` extraction section updated, new `docs/adding-an-extractor.md` (following `adding-a-provider.md`), `.env.example` updated with the new optional vars, CHANGELOG `2.1.0` entry including both re-embed release notes. Deploy to Railway staging, run the integration fixtures, then production. **In progress** → [progress](progress/M29-docs-and-release.md): all docs, `.env.example` and the CHANGELOG `2.1.0` entry done; staging/production deploy not started.

## Explicitly deferred (v2.x fast-follows)

- **OCR**: scanned PDFs (still `scanned-pdf-ocr-not-implemented`) and images (`image/*`). Needs a vision/OCR model or service. Candidate tie-in with GraceSoft's own self-hosted AI services rather than a paid third party.
- Legacy `.ppt`, `.rtf`, `.epub`, Apple iWork (`.pages`/`.numbers`/`.key`).
- Google Drawings, Forms, Sites, Jamboard.
- Audio/video transcription.
- Drive shortcuts (still not followed, per `walkFolderTree`).
- Embedded images inside Office documents (text only for now).

## Non-goals

- No change to the vector ID scheme, retrieval/MCP response *shapes* (fields are only added), or required env vars. Any of those would make this a v3.
- No conversion through Drive (e.g. `files.copy` into a Google Doc). The service account is deliberately `drive.readonly` and must never create files in a user's Drive.
