# GraceSoft DriveSync — Testing Checklist (v2.1 Document Type Expansion)

Target coverage for the v2.1 milestones (M19–M29) in `06-v2.1-milestone-checklist.md`. **Status (2026-11-21):** unit, observability and most docs items done; integration, real-file security checks and the staging run remain. Follows the v2 conventions: extractors are tested against injected fakes in unit tests, and real libraries and real Drive files are tested in integration tests.

## Unit tests

- [x] **Registry refactor is behaviour-neutral (M20)**: every pre-existing `textExtractor.test.ts` case (Doc, Slides, Sheet, PDF-with-text, PDF-without-text, unsupported type) passes **unmodified** against the new registry-based dispatcher. — verified at the M20 commit; the Sheets case was then deliberately rewritten in M24.
- [x] **Registry dispatch**: each registered MIME type routes to exactly one extractor; an unregistered MIME type returns `{ ok: false, reason: "unsupported-mime-type" }` and never calls `downloadFile`. (`registry.test.ts`)
- [x] **No duplicate registrations**: a test fails if two extractors claim the same MIME type, which prevents a contributor silently shadowing an existing one. (`registry.test.ts`, including the production set)
- [x] **Size guard (M21)**: a file whose `size` exceeds `MAX_EXTRACT_BYTES` returns `file-too-large` and `downloadFile` is **never called**. A file at exactly the limit passes. Google-native files (no `size`) skip the check. (`guards.test.ts`)
- [x] **Timeout (M21)**: a fake parser that never resolves returns `extraction-timeout` within the configured window, and doesn't leave the sync run hanging. (`guards.test.ts`)
- [x] **Zip-bomb guard (M21)**: an archive whose declared/actual decompressed size or entry count exceeds the cap returns `archive-too-large` before full decompression. — declared size and entry count, checked from the central directory before inflating (`guards.test.ts`).
- [x] **Env parsing**: `MAX_EXTRACT_BYTES`, `EXTRACT_TIMEOUT_MS` and `GOOGLE_DOCS_EXPORT_FORMAT` are optional with documented defaults. Invalid values (negative, non-numeric, unknown format) fail fast at startup with a clear message (`src/config/env.test.ts`).
- [x] **docx (M22)**: Word headings come out as Markdown `#` headings; body text, lists and tables are preserved as readable text. A corrupt buffer returns `corrupt-file`. A password-protected file returns `password-protected`. Neither throws. — against the real mammoth with an in-code docx fixture (`formats.test.ts`).
- [x] **doc (M22)**: legacy Word text extracted; corrupt input fails closed. — text via an injected fake reader; corrupt input through the real word-extractor.
- [x] **Plain-text family (M23)**: UTF-8 with and without BOM decodes identically (BOM stripped). Invalid UTF-8 returns `unsupported-encoding`. JSON is pretty-printed. HTML drops `<script>`/`<style>` content and keeps headings as Markdown. An empty `.txt` returns `{ ok: true, text: "" }` and produces zero chunks without error.
- [x] **Spreadsheets (M24)**: a multi-sheet workbook produces one `## <Sheet name>` section per sheet, in workbook order. Empty sheets are omitted. Formula cells give their computed values, not formulas. Hidden sheets: behaviour matches the decision recorded in the progress doc. — hidden sheets are **omitted** (M24 progress doc).
- [x] **Google Sheets re-route (M24)**: Google Sheets now call `exportAsText` with the xlsx MIME type and go through the spreadsheet parser, not the old `text/csv` path. — via the new binary `exportFile(id, xlsx MIME)`, not `exportAsText`.
- [x] **Presentations / ODF (M25)**: pptx/odp slide text comes out in slide order. Speaker notes are included or excluded per the recorded decision. odt body text and headings are extracted. — speaker notes **included**.
- [x] **Docs export flag (M26)**: `GOOGLE_DOCS_EXPORT_FORMAT=text` (default) still calls `exportAsText(id, "text/plain")`. `markdown` calls `exportAsText(id, "text/markdown")`. Google Slides is unaffected by the flag.
- [x] **Chunker picks up Markdown headings**: Markdown from docx and Google Docs (markdown mode) produces chunks whose `section` matches the real heading, end-to-end through `chunkText`. — end-to-end for docx; Google Docs Markdown mode relies on the same `#` heading path.
- [x] **Skipped state (M27)**: a permanent-reason failure is recorded as `SKIPPED` with its `modifiedTime`. On the next run with an unchanged `modifiedTime` it is **not** re-extracted or re-logged. Once `modifiedTime` changes it **is** retried. Transient failures (thrown error, timeout) are never marked `SKIPPED` and are retried every run, as today. (`syncFolder.test.ts`)
- [x] **Skipped → supported transition**: a file previously `SKIPPED` as `unsupported-mime-type` gets synced after a deploy adds support for its type, without the user having to touch the file. (Decide the mechanism: e.g. re-evaluate `SKIPPED` rows whose reason is `unsupported-mime-type` when the registry gains that type. Record it in the M27 progress doc.) — mechanism: `capabilityVersion` stored on every SKIPPED row; a changed version retries the file once (M27 progress doc).
- [x] **Metadata (M28)**: upserted vectors include `mimeType`. Retrieval and MCP results include it. Vectors written before M28 (no `mimeType`) still return without error.

Assert on known text and headings. — **partial:** in-code fixtures run through the real mammoth, word-extractor (corrupt path), html-to-text and fflate for docx, xlsx, ods, pptx, odp, odt, txt, md, csv, tsv, json, html. Still missing: committed files saved by real Office/LibreOffice, and a real `.doc`. `.xls` is deferred.
- [ ] **Real Drive end-to-end**: upload one of each fixture to a real test Drive folder shared with the service account, run a real sync, and confirm each file is `added` with chunks in the vector store and a `DriveFile` row in Postgres. Closes v2's still-open "Extraction across file types" integration item for the original four types too.
- [ ] **Real Google Sheets multi-tab**: a real multi-tab Google Sheet is exported as xlsx and every tab ends up in the vector store.
- [ ] **Real Google Docs Markdown export**: with the flag on, a real Doc with H1/H2 headings syncs with correct `section` metadata.
- [ ] **Modify / delete across new types**: editing a docx in Drive triggers `updated` with stale vectors cleaned up if chunk count shrinks. Deleting it removes all its vectors (same M10 guarantees, now for binary types).
- [ ] **Prisma migration (M27)**: the new migration applies cleanly on top of v2's three migrations, both on a fresh DB and on a copy of a populated v2 DB. Existing rows default to `SYNCED`.
- [ ] **Retrieval & MCP against new types**: a query matching content that only exists in a docx/xlsx/pptx returns that chunk with correct attribution (and `mimeType`) via both REST and MCP.

## Security & resilience tests

- [ ] **Zip bomb fixture**: a real crafted high-compression docx/xlsx is rejected as `archive-too-large`, worker memory stays bounded, and the rest of the folder's sync continues.
- [ ] **Oversized file**: a real file above `MAX_EXTRACT_BYTES` in a real Drive folder is never downloaded (confirm via logs / Drive API call count).
- [x] **Malformed files**: a truncated docx, a renamed `.exe` → `.docx` and a corrupt xlsx each fail closed with a specific reason and don't halt the folder or other accounts' syncs. — truncated docx, renamed `.exe` → `.docx` and a workbook-less xlsx all fail closed (`guards.test.ts`, `formats.test.ts`); `syncFolder` continues past failed files (existing test). Real-Drive confirmation still pending.
- [x] **No script execution**: HTML fixtures with `<script>` and docx/xlsx with macros or external references: nothing is executed or fetched, and only text is extracted. Spreadsheet formulas are never evaluated against external sources. — HTML scripts/styles/link targets dropped, formulas never evaluated (cached values only, tested with `WEBSERVICE`), mammoth runs with `externalFileAccess: false`, OPC external relationships ignored. Real macro-bearing files not yet tried.
- [x] **Parser dependency audit**: `npm audit` is clean for all newly added parsers. The chosen spreadsheet library is not the unmaintained npm `xlsx@0.18.5`. — the new parsers (`mammoth`, `word-extractor`, `html-to-text`, `fflate`) add **no** `npm audit` findings; the 14 existing findings all come from pre-existing deps (googleapis, openai/zod, MCP SDK, express). No `xlsx` package at all.
- [ ] **Memory under load**: a folder with many mid-sized Office files syncs without the worker exceeding its Railway memory limit (watch the metrics during the staging run).
